# Release checklist 0.1.0

The checks to run before release 0.1.0 on every platform. Rows that an automated test covers are marked with the test that proves them (run with `npm run test:e2e`, `npm test` and `npm run test:gateway` on the release commit). Rows with an empty Result need a person with the device; write the date, the build and "OK" or what went wrong.

The end-to-end tests run on Chromium in three viewports (desktop 1440x900, iPhone 14, Pixel 7) with the network mocked. They do not replace the installers, Safari on iOS, the real Google sign-in, printers or banking apps, which are the manual rows below.

## macOS (Apple Silicon and Intel)

| Platform | Step | Expected | Result |
|---|---|---|---|
| macOS Apple Silicon | Install the universal dmg, drag to Applications | The app is copied; the first start is blocked by Gatekeeper (no paid signature) | |
| macOS Apple Silicon | Run `xattr -cr "/Applications/WE Invoice.app"` as the README says, start again | The app starts and shows the dashboard | |
| macOS Intel | Same install and `xattr` steps on an Intel Mac | The universal build starts on Intel too | |
| macOS | Close the window | The app stays in the tray (menu bar) and the scheduler keeps running | |
| macOS | Sign in with Google from the start offer | The browser opens Google, the app comes back signed in and asks for the encryption password | |
| macOS | Turn encryption on, confirm three recovery words | Toast "Šifrovanie je zapnuté"; the folder WE Invoice in Drive holds only `.enc` files | Automated: `tests/e2e/encryption.spec.js` (web build, Drive mocked) |
| macOS | Edit on this Mac and on a second device, sync both | Both changes are there; a number taken twice gets a new one on one device | Automated: `tests/e2e/sync-devices.spec.js` (web build, Drive mocked) |
| macOS | Install 0.1.0 over the previous build | The update keeps the data and the key; no password asked | |
